# Upgrading format-2 repositories

The implemented [upgrade contract](runtime-upgrade-api-draft.md) initially shipped one concrete storage-1-to-storage-2 edge. The [original certificate](runtime-upgrade-certification.json) names that predecessor and target. It does not authorize arbitrary future builds to open the resulting format-2 repository.

The next transition uses storage 3, preserving the approved commands and compatibility rules. A storage-2-to-storage-2 candidate failed the actual predecessor writer test and is not certified. Its predecessor executable is retained at `/tmp/effectory-format2-upgrade-baseline/effectory-darwin-arm64`, SHA-256 `02c99046b503871a62a6b50c579ad83ba8e2ade44ae3ad78b80ce72029a058d0`, build `677f3350bff79f245d1fe4f76ef98610767981875529cf5948949bbefd507cdc`. That correction passed its real executable matrices and required checks; the historical results are recorded below. The subsequent [HTTP disconnect correction](runtime-http-disconnect-evidence.md) has its own four-transition certificate.

## Resolved source boundaries

- The executor now accepts either supported source format, but still requires an exact certified source identity and target contract/platform. An unsupported platform refuses before acceptance.
- The independently verified recovery image supplies the previous completed receipt, envelope owner and raw runtime marker. Partially transferred source files never decide what the previous owner was.
- Credential and extension envelopes transfer to the new acceptance. Abort restores the exact previous bytes when the logical value is unchanged, or preserves a changed logical value under the prior owner. Foreign envelope owners refuse explicitly.
- A populated format-2 vault retains its schema and encrypted contents. An empty sentinel changes ownership through a complete staged replacement and atomic rename. An initial in-place implementation failed SIGKILL tests because it left a rollback journal that inspection correctly refused; the replacement avoids creating such a source journal. Private staging cleanup remains restartable.
- Publication replaces only the exact verified old runtime marker. The new marker is storage format 3, which the actual format-2 predecessor rejects. The old completed receipt remains unchanged; the validator recognizes the exact old format-2 migration list and the exact new format-3 list separately. Vault SQLite remains version 2; the repository marker is a distinct format boundary.
- Startup enforces the accepting build. Current offline vault, extension and run-reclamation entry points now explicitly enforce that same owner before opening storage. The retained predecessor did not enforce it for all offline writers, which is why changing the repository format is necessary. Explicit edges identify the retained legacy and format-2 predecessors separately.

## Executable proof extension

The proof runner's optional `--bootstrap` path seeds a real format-2 repository through the legacy-to-current transition. A completed manual task and open approval remain pinned to that legacy revision while the current executable admits another revision. The target and restored predecessor must finish both without repeating either completed manual handler. Neither manifests nor source build labels are rewritten.

The lifecycle matrix retains timers, retries, manual authorization, reports, reader/report protection, schedules, vault state and request-key receipts. A deterministic checkpoint uses the exact target source, checks its ABI against the compiled target, and stops after credential transfer. The actual predecessor's offline commands must refuse without changing repository bytes; the actual target executable then resumes that accepted transition. This checkpoint is source-driven, not a claim that the compiled CLI was killed at that exact instruction. Separate subprocess tests SIGKILL every executor phase, abort stage and empty-sentinel installation boundary.

The deliberately incompatible executable fixture uses the candidate runtime source with only the execution contract and test certification policy changed. Its embedded agent instructions predate the documentation-only release refresh. It must refuse pending work, preserve archived inspection after settlement, and reject historical operations requiring incompatible code. That test contract does not ship. Bundle pruning and its public preview/deletion policy remain separate.

## Rejected candidate and corrected boundary

The real `677f…` predecessor's `run reclaim plan` returned exit 0 and changed `state.sqlite` on a disposable copy of the first format-2 target candidate. Its shared format decoder accepts another build's completed format-2 receipt; daemon refusal alone did not fence this offline writer. Evidence is `/tmp/effectory-format2-upgrade/writer-counterexample.json`. That candidate, build `42fc52fa3447341fa522a6c8813b5efb15aba10db976175e59e0ee96eb83303f`, is not certified despite passing replay and rollback. The in-progress full suite was interrupted with exit 130 when this was found; it is not a passing check.

The corrected candidate is build `fe46ad3fa836f61192ee29d76695082ced3d571857716442a22031e45eef79a2`, executable SHA-256 `a69d21b724f053b90453e29d9dd408523c4cfc40b76974bdebcc4ff302a286bf`. Both source formats 1 and 2 now upgrade to storage 3. No native workflow rows, revision IDs, retained bundles or encrypted vault contents are rewritten. The new marker fences the actual predecessor, while the explicit writer-owner check prevents this implementation from granting future same-format writers permission merely because it can decode their metadata.

Final isolated verification passed typecheck, formatting/lint and **748 tests, zero failures, 6,317 assertions across 169 files** (1,419.95 seconds).
